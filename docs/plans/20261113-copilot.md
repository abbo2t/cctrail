# GitHub Copilot in VS Code

Read the chat history of GitHub Copilot in VS Code as a fifth source, `--provider vscode`, beside
Claude Code, Codex, pi and fx. One PR per phase.

## What is known

Checked in phase 1 on real history from VS Code stable 1.146 on macOS (Copilot Chat 0.74, now
bundled with VS Code under `extensions/copilot`), with sessions written by versions from before
1.109 up to 1.146. Not checked: Insiders, Linux, Windows, WSL, SSH, Codespaces, edit mode.

**Where**

- `<User>/workspaceStorage/<hash>/chatSessions/<sessionId>.jsonl` (or legacy `.json`);
  `<User>/globalStorage/emptyWindowChatSessions/` for windows without a folder. `<User>` is
  `~/.config/Code/User` (Linux), `~/Library/Application Support/Code/User` (macOS),
  `%APPDATA%\Code\User` (Windows); Insiders has `Code - Insiders`. Many `<hash>` folders have no
  `chatSessions`. `profiles/<id>/` holds no chat sessions.
- `<hash>/workspace.json` has either `folder` (a `file://` or `vscode-remote://` URI) or
  `workspace` (a `.code-workspace` file, or an untitled `…/Workspaces/<id>/workspace.json`).
- Dev containers: sessions stay on the client, in the local `workspaceStorage`. The URI is
  `vscode-remote://dev-container%2B<hex>/workspaces/<name>`, where `<hex>` is hex-encoded JSON
  whose `hostPath` is the local folder: map the session to that, not to `/workspaces/<name>`.

**Session log**

- A `.jsonl` line is `{kind, k, v}` (plus `i` on some pushes): kind 0 the whole initial document
  (first line), 1 set `v` at key path `k`, 2 push the items of `v` onto the array at `k`, 3
  delete. With `i`, a push first truncates the array to `i` items (a splice); seen only on
  `requests[n].response`. Kind 3 never appeared in real history; a fixture covers it anyway. No
  truncated lines appeared either.
- The document's `version` is 3 in every file, `.json` and `.jsonl`: it does not identify the VS
  Code version, nothing in `chatSessions` does.
- A `.jsonl` can start with a document migrated from an older `.json` (its kind 0 holds all
  earlier requests, and `creationDate` predates 1.109), and the old `.json` may stay beside it
  with the same request ids: the `.jsonl` wins, by session id. Most legacy `.json` files hold no
  requests at all.
- Document: `sessionId`, `creationDate` (ms), `requests[]`, `customTitle`, `inputState` (draft
  input, the most frequent line kind, irrelevant).

**Request**

- `requestId`, `timestamp` (ms, the prompt), `message.text`, `modelId`, `modeInfo.kind` (`agent`;
  absent in ask mode and older requests), `response[]`, `result`.
- End: `modelState = {value, completedAt}`; `completedAt - timestamp` matches
  `result.timings.totalElapsed`. `value` 1 completed, 2 cancelled (inferred: no result), 3 failed
  (`result.errorDetails`). Older requests have no `modelState` and no `modelId`.
- Activity inside a turn: `result.metadata.toolCallRounds[]` is one entry per model call, and
  newer ones carry `timestamp` (always within the request's span) and `modelId`; older rounds
  have neither. A long agent turn therefore has dated steps when the rounds are dated.
- Model: `modelId` is `copilot/<family>` with dots (`copilot/claude-opus-4.8`, `copilot/gpt-4.1`,
  `copilot/auto`); bring-your-own-key models look like `customoai/<name>/<name>`.
  `result.metadata.resolvedModel` is the API id when present (`claude-opus-4-8`,
  `claude-haiku-4-5-20251001`, `gpt-5.4-2026-03-05`), and it is how `auto` resolves; a round's
  `modelId` is the family again. Some `auto` requests carry neither: model unknown.
- Subagents: a `toolInvocationSerialized` response part with `toolId` `runSubagent` or
  `execution_subagent` and `toolSpecificData {agentName, modelName (display name), credits?}`. No
  tokens for the subagent in `chatSessions`.

**Tokens and charges**

- On newer requests: `promptTokens` is the prompt of the **last** model call only (equal to
  `result.metadata.promptTokens`), `completionTokens` is the output **summed** over the request's
  model calls (`result.metadata.outputTokens` is the last call's). `promptTokenDetails` gives
  percentages by category, no counts. `result.usage` repeats the same three fields on some
  requests. Older requests have only the metadata pair, the oldest none.
- So `chatSessions` never has a request's total input or its cache reads: it cannot price an
  agent turn at API rates. Output tokens are exact, except for calls it leaves out.
- `copilotCredits` (float, on newer requests) is Copilot's own charge: exactly the sum of the debug
  log's `copilotUsageNanoAiu` / 1e9 for the main session's calls. Its dollar value is unknown.

**Debug logs**

- `<User>/workspaceStorage/<hash>/GitHub.copilot-chat/debug-logs/<sessionId>/` (empty windows:
  `<User>/globalStorage/github.copilot-chat/debug-logs/`): `main.jsonl`, one file per subagent
  (`runSubagent-<label>-<toolCallId>.jsonl`, `executionSubagent-<toolCallId>.jsonl`, linked by
  `session_start.attrs.parentSessionId` and the parent's `child_session_ref`), a title file, and
  prompt and tool snapshots.
- Off by default (`github.copilot.chat.agentDebugLog.fileLogging.enabled`); keeps the last 50
  sessions (`maxRetainedSessionLogs`), at most 100 MB each. Only a few sessions have one.
- Lines are spans `{ts, dur, sid, type, attrs}`; `type: llm_request` is one model call with
  `attrs.model` (family), `debugName` (`panel/editAgent`, `summarizeConversationHistory`,
  `runSubagent`, the title), `inputTokens`, `outputTokens`, `cachedTokens` (always below
  `inputTokens`: input includes cache reads, inferred) and `copilotUsageNanoAiu` (absent on title
  calls). `session_start.attrs.vscodeVersion` names the version.
- It has calls `chatSessions` misses: subagents, history summarization and titles. Where both
  exist, the main agent's output sums match `completionTokens`.
- `globalStorage/github.copilot-chat/session-store.db` (SQLite: sessions, turns, files) has no
  tokens or models.

## Decisions to agree first

- **Source:** `chatSessions` for sessions, time and models, since it always exists. Debug logs
  only as an optional fallback for tokens, when present, or not at all. Recommended: start
  without them (phase 2 and 3 on `chatSessions` only), add them as a later phase if wanted.
- **Tokens:** output from `completionTokens` (else `result.metadata.outputTokens` of a single-call
  request); no input, since what is logged is one call's prompt, not the turn's input. Requests
  with neither count for time and sessions only, listed below the report like unpriced models.
  No tokenizer estimates: cctrail's numbers are exact or absent.
- **Cost:** API prices need input, which only the debug log has. Without it the cost column for
  VS Code is output only, which understates it badly; recommended: no API-price cost for VS Code,
  and `copilotCredits` shown as the harness's own charge (`Event.cost`) only if its dollar value
  can be established (GitHub's billing docs); otherwise cost stays empty.
- **Catalog:** Copilot runs Gemini and Grok too, the catalog has only `anthropic` and `openai`.
  Adding `google` and `xai` to `scripts/pricing-history.py` is its own phase; until then those
  tokens are listed as unpriced.
- **CLI:** `--provider vscode` (reserving `copilot` for a future Copilot CLI provider) and `p` in
  the interactive view gain a value; `schema_version` stays, a new provider name is no schema
  change. Both need the person's approval.
- **Scope:** VS Code chat (ask, edit, agent modes) only. Not inline completions (nothing is
  logged), not Copilot CLI (`~/.copilot`, which will use `--provider copilot` in the future), not
  the cloud coding agent.

      where request time, end time, model, tokens and charges are; what `auto` resolves to and
      where; how a subagent's calls and tokens appear; what a cancelled or failed request leaves.
- [ ] The same on Insiders, in edit mode, and for an edited, retried, forked or moved chat (none
      in the history read so far).
- [x] Compare `chatSessions` with the debug logs: which one has every model call with its tokens,

      a fallback.
- [x] Check the remote cases: dev containers.
- [ ] The same for WSL, SSH and Codespaces: where the sessions end up and what `workspace.json`

- [x] Hand-write minimal fixtures in `tests/fixtures/vscode/` for each format quirk found: a

      tokens, a cancelled and a failed request, a truncated last line, a debug log with a

- [x] Update this plan with the findings; drop phases they make pointless.

### 2. Reading sessions

- [ ] `Provider::Vscode` (`vscode`) in `model.rs`, `parse_history`, `--provider` and its error
      text, the interactive view's provider switch, `db` export and import.
- [ ] `src/parser/vscode.rs`: roots per OS for stable and Insiders, `CCTRAIL_VSCODE_DIR` (only
      cctrail reads it, like `FX_HOME`) replacing them with one `User` directory; tests use it.
- [ ] Replay the change log into the document with a small own routine; skip lines and paths that
      don't apply, never fail on them. A legacy `.json` is the document itself.
- [ ] The working directory from `workspace.json`: a `file://` URI decoded to a path, a
      dev-container URI to the `hostPath` in its hex-encoded authority, another remote URI to its
      path on the remote, a multi-root workspace to the first folder of its `.code-workspace`
      file; empty-window sessions get no project.
- [ ] Events: the prompt (`timestamp`), each dated tool round and the end (`completedAt`) as
      activity; a request without dated rounds is the prompt and the end only, not its whole span.
      The model from `resolvedModel`, else `modelId` without `copilot/` and with dots as dashes
      (`claude-sonnet-4.5` as `claude-sonnet-4-5`); `auto` that never resolved stays `auto`.
- [ ] Unit tests: replay (set, push, delete, bad paths), URI decoding on Unix and Windows paths,

- [ ] `make compare` against `main` with VS Code chat history absent: identical.

### 3. Tokens and cost

- [ ] Output tokens from `completionTokens`, else `result.metadata.outputTokens` when the request

- [ ] Subagents: `chatSessions` has no tokens for them, so they stay uncounted unless debug logs
      are read (a later phase, if the source decision wants it).
- [ ] Cost as decided above: `copilotCredits` as `Event.cost` only if its dollar value is
      established, no API-price cost from output alone.
- [ ] Sessions without tokens: time counted, a line below the report with how many.
- [ ] Unit tests for the dedupe, the subagent rule and the pricing of a Copilot model id.

## Open questions

- The dollar value of a Copilot credit (`copilotUsageNanoAiu` / 1e9).
- Whether `inputTokens` in the debug log includes `cachedTokens` (it is always larger; confirm
  from the extension's source before pricing with it).
- Forks of VS Code that keep the same layout (VSCodium, Cursor's Copilot extension): out unless
  asked.
- Deleted chats: VS Code removes the file, so the history is only what is still there;
  `cctrail export` is the way to keep it.
