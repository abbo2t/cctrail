# GitHub Copilot in VS Code

Read the chat history of GitHub Copilot in VS Code as a fifth source, `--provider vscode`, beside
Claude Code, Codex, pi and fx. One PR per phase.

## What is known

- Sessions live in VS Code's user data, not in a dot-directory: `<User>/workspaceStorage/<hash>/
  chatSessions/<session>.jsonl`, with `<hash>/workspace.json` naming the folder (`file://` or
  `vscode-remote://` URI); chats of a window without a folder are in
  `<User>/globalStorage/emptyWindowChatSessions/`. `<User>` is `~/.config/Code/User` (Linux),
  `~/Library/Application Support/Code/User` (macOS), `%APPDATA%\Code\User` (Windows); Insiders
  and remote servers (`~/.vscode-server/data/User`) have their own.
- Since VS Code 1.109 a session is an append-only log of changes to one JSON document: a line has
  a `kind` (0 the initial state, 1 set, 2 push, 3 delete), a key path and a value. Before it, a
  session was one `.json` file rewritten on every save; a `.jsonl` wins over a `.json` of the
  same id.
- The replayed document has `sessionId`, `creationDate` and `requests[]`; a request has an id, a
  timestamp, the prompt (`message`), `modelId`, `response[]` (text, tool calls, `runSubagent`) and
  `result` with timings and metadata.
- Tokens are the weak part. Some results carry `promptTokens` and `outputTokens`, some carry
  neither, none splits cache reads from input; legacy `.json` sessions have none. A newer field,
  `copilotUsageNanoAiu`, is Copilot's own charge for a call. The extension's debug logs
  (`GitHub.copilot-chat/debug-logs/<session>/`) may hold every model call, title generation
  included.
- These come from third-party tools' docs, not from VS Code's source or real files: phase 1
  checks every one of them.

## Decisions to agree first

- **Sessions without tokens:** count their time and sessions, leave tokens and cost empty and list
  them below the report like unpriced models. No tokenizer estimates: other tools guess from the
  text, cctrail's numbers are exact or absent.
- **Cost:** at API prices like the other harnesses, so Copilot compares with a subscription the
  same way. All input counts as uncached, which overstates it; say so in the readme.
  `copilotUsageNanoAiu`, if it converts to dollars, is the harness's own estimate (`Event.cost`)
  for models the catalog lacks.
- **Catalog:** Copilot runs Gemini and Grok too, the catalog has only `anthropic` and `openai`.
  Adding `google` and `xai` to `scripts/pricing-history.py` is its own phase; until then those
  tokens are listed as unpriced.
- **CLI:** `--provider vscode` (reserving `copilot` for a future Copilot CLI provider) and `p` in
  the interactive view gain a value; `schema_version` stays, a new provider name is no schema
  change. Both need the person's approval.
- **Scope:** VS Code chat (ask, edit, agent modes) only. Not inline completions (nothing is
  logged), not Copilot CLI (`~/.copilot`, which will use `--provider copilot` in the future), not
  the cloud coding agent.

## Phases

### 1. Format, on real history

- [ ] Read real sessions from VS Code stable and Insiders, old and new, in every mode, and write
      down per version: where request time, end time, model, tokens and charges are; what `auto`
      resolves to and where; how a subagent's calls and tokens appear; what an edited, retried or
      cancelled request leaves; what a forked or moved chat copies.
- [ ] Compare `chatSessions` with the debug logs: which one has every model call with its tokens,
      which exists by default, how long each is kept. Pick one as the source, the other as none or
      a fallback.
- [ ] Check the remote cases: WSL, SSH, dev containers, Codespaces. Where the sessions end up and
      what `workspace.json` says.
- [ ] Hand-write minimal fixtures in `tests/fixtures/vscode/` for each format quirk found: a
      `.jsonl` log with all four kinds, a legacy `.json`, an empty-window session, a request
      without tokens, a truncated last line. No real history.
- [ ] Update this plan with the findings; drop phases they make pointless.

### 2. Reading sessions

- [ ] `Provider::Vscode` (`vscode`) in `model.rs`, `parse_history`, `--provider` and its error
      text, the interactive view's provider switch, `db` export and import.
- [ ] `src/parser/vscode.rs`: roots per OS for stable and Insiders, `CCTRAIL_VSCODE_DIR` (only
      cctrail reads it, like `FX_HOME`) replacing them with one `User` directory; tests use it.
- [ ] Replay the change log into the document with a small own routine; skip lines and paths that
      don't apply, never fail on them. A legacy `.json` is the document itself.
- [ ] The working directory from `workspace.json`: a `file://` URI decoded to a path, a remote URI
      to its path on the remote, a multi-root workspace to its first folder; empty-window sessions
      get no project.
- [ ] Events: the prompt and the end of each request as activity, usage on the request when it
      has tokens, the model through `model_id` (`copilot/claude-sonnet-4.5` as
      `claude-sonnet-4-5`). A long agent turn with no dated steps inside is one window, not its
      whole span: decide in phase 1 whether tool calls carry times.
- [ ] Unit tests: replay (set, push, delete, bad paths), URI decoding on Unix and Windows paths,
      `.jsonl` over `.json`. A CLI test on the fixtures: `--provider vscode --json`.
- [ ] `make compare` against `main` with VS Code chat history absent: identical.

### 3. Tokens and cost

- [ ] Usage from the fields phase 1 found; a request counted once across its `.json` and `.jsonl`
      copies, retries and forks (by request id).
- [ ] Subagents (`runSubagent`): child sessions linked with `inherit_roots` if they are logged
      apart, else their tokens stay in the parent request; never both.
- [ ] `Provider::Vscode` prices from every catalog; the dated-id fallback in `pricing::lookup`
      covers it. `copilotUsageNanoAiu` as `Event.cost` if phase 1 found its dollar value.
- [ ] Sessions without tokens: time counted, a line below the report with how many.
- [ ] Unit tests for the dedupe, the subagent rule and the pricing of a Copilot model id.

### 4. More catalogs

- [ ] `google` and `xai` in `scripts/pricing-history.py` and `pricing.tsv`, read only by VS Code,
      pi and fx. Check `make compare`: pi and fx tokens on those models gain a price, a change in
      the numbers to describe in the PR.

### 5. Swears and docs

- [ ] Prompts for the Swears view: `message.text` without attached files, selections and `#`
      references, counted toward the model that answered last; agent-written subagent prompts
      excluded. A fixture in `tests/swears/vscode/`.
- [ ] Readme: the intro, the History table (paths per OS, `CCTRAIL_VSCODE_DIR`), `--provider`,
      the `p` key, a paragraph on what VS Code chat logs and what its cost leaves out. `agents.md`:
      scope, the module list, the never-write list. Roadmap phase ticked, this plan completed.
- [ ] `docs/perf.md`: the cost of replaying large sessions on a real history; responses hold full
      text, so skip their values unparsed if it shows.

## Open questions

- Whether tokens are there often enough for the cost column to mean anything, or VS Code chat is a
  time-only harness with partial tokens. Phase 1 answers it; if it is the latter, phases 3 and 4
  shrink to "show what there is".
- Forks of VS Code that keep the same layout (VSCodium, Cursor's Copilot extension): out unless
  asked.
- Profiles: whether `User/profiles/<id>/` holds its own empty-window sessions.
- Deleted chats: VS Code removes the file, so the history is only what is still there;
  `cctrail export` is the way to keep it.
